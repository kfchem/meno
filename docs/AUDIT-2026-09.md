# Stabilization audit — September 2026

A repository-wide review of Meno at `main` @ `25a4b7a`, carried out before the
second stabilization PR. Each finding is rated on two axes:

- **Severity** — user or developer impact if left alone (High / Medium / Low).
- **Fix risk** — how likely a fix is to regress behaviour or GUI feel
  (Low / Medium / High).

Status: **PR** = addressed in the stabilization PR that adds this document;
**#2** = covered by the open PR #2; **Open** = backlog / issue candidate.

Baseline at the time of the audit: `npm run build` passed, `npm run lint`
passed with 13 warnings, there were no frontend tests, and no CI. Rust could not
be compiled on the audit machine (no MSVC build tools), which is why Rust-side
findings are left open and are verified through CI instead.

## Correctness bugs

| ID | Finding | Sev | Risk | Status |
| --- | --- | --- | --- | --- |
| B1 | Format detection treats any file whose first line is an integer as XYZ, before looking for MOL markers. MOL/SDF files whose title line is a number — e.g. PubChem SDFs, which use the CID as the title — are routed to the 3D viewer and parsed as XYZ, producing garbage. Affects both `detectFormat` and OmniHub's own `isXyz`. | High | Low | PR |
| B2 | RXN reactant/product counts are read from the first header line containing two integers. A reaction name such as `step 1 of 2` is mistaken for the counts line, so molecules are assigned to the wrong side of the arrow. The CTfile spec fixes the counts line at line 5. | Medium | Low | PR |
| B3 | The 2D editor keeps a module-level store registry keyed by `tabId`. The workflow editor passes its React Flow node id (`"mol2d"`) as `tabId`, so **every Workflow Builder tab shares one sketch store**, and closing one tab deletes the registry entry the others still use. | High | Low | PR |
| B4 | Python console: event listeners are registered asynchronously inside an effect keyed on `pid`. Output emitted between spawn and re-subscription (e.g. the auto-run `AUTO OK`) is dropped, a fast cleanup can leak listeners (duplicated lines under React StrictMode), and a failed `Start` (missing `uv`, network error) gives no feedback. | Medium | Low | PR |

| B10 | Rust: log/stdout readers did blocking reads inside async tasks, occupying async worker threads for the child's lifetime (on a low-core machine the uv log pipes could starve and stall `uv`). `py_env_setup_uv` still blocks one async worker while waiting for `uv`. | Medium | Low | Readers fixed (sidecar hardening PR); the wait is open |

## Security (Tauri commands and process execution)

| ID | Finding | Sev | Risk | Status |
| --- | --- | --- | --- | --- |

| S4 | File-system capabilities are scoped to `$RESOURCE` / `$APPDATA` / `$APPLOCALDATA`; no shell plugin is enabled. Reasonable as is. | — | — | OK |

## Suggested issue order (after this PR and #2 land)

1. **S1 + A5** — Harden sidecar/uv commands: resolve paths in Rust from enums; reject traversal. Add Rust unit tests for path validation.
2. **B7 + S3** — Reap exited sidecars, kill children on app exit, avoid `unwrap()` on the process mutex.
3. **B9 + G1** — User-visible import errors (toast or inline message) and a visible "Open" action in the 2D editor.

8. **G4** — Mark the workflow editor as a preview and persist node parameters in tab data.

## The network, after the audit

The audit predates Meno's network (#49): the app's proxy that every
connection goes through, offline mode, and the record
(`docs/ARCHITECTURE.md`, The network). Looked at in October 2026:

| ID | Finding | Sev | Risk | Status |
| --- | --- | --- | --- | --- |
| N1 | The console's sidecar was routed only when its task began. Offline, the task was refused and the sidecar started with no proxy at all, so the code run in it could go out directly, past offline mode and the record. | High | Low | Fixed (network gaps PR): a child that may not go out - another worker, or the console while offline - is pointed at the proxy with no task, and is refused and recorded (`Net::route_sidecar`). |
| N2 | The proxy's port was known only once the async runtime had bound it. A child started before that got no proxy variables, and went out on its own. | Medium | Low | Fixed (network gaps PR): the port is bound as the app starts, before anything can be started; should it fail, children are pointed at port 0 and reach nothing. |
| N3 | Offline mode and the purposes allowed came to the app only once the window had loaded its settings. Until then the app took itself to be online, so the console - the user's own code, which needs no asking - could go out though the user had chosen offline. | Medium | Low | Fixed (network gaps PR): the app reads them from `settings.json` as it starts (`Net::load_settings`). The window brings them in again when it loads. |
| N4 | The proxy holds what honours proxy variables: uv, pip, Python's `urllib`, `requests`. Code in the console that opens a socket of its own, or ignores those variables, is not held by it. Meno does not sandbox the console. | Medium | High | Open: documented as a limit (`docs/ARCHITECTURE.md`). Holding it would take the operating system's sandboxing. |

## Found by driving the built app (see `scripts/gui/`)

| ID | Finding | Sev | Status |
| --- | --- | --- | --- |
| H1 | **Fit to content clips labels at the edge.** `FitToContent2D` takes its bounding box from atom positions alone, so anything a label reaches past its atom falls outside the fit. Opening `scripts/gui/fixtures/depiction-check.mol` and pressing Fit leaves the `H` of `H2N` running off the left edge - column 0 of the window is solid ink. `layout2d`'s own `Layout.bounds` does account for labels; the camera fit does not use it. | Medium | Fixed (PR) |
| H2 | **Some atoms cannot be picked up at all.** `Atoms2D` places its pick circles by rewriting an `InstancedMesh`'s instance matrices and never tells three.js they moved. `InstancedMesh.raycast` first tests a bounding sphere that it computes on the first raycast and then keeps, so an atom outside that sphere is never hit. On a Mac, with `depiction-check.mol` open, the `OH` oxygen of the hashed-wedge centre could be dragged; a chain carbon, a chain end and the wedge stereocentre could not, though each lit its hover ring, which is worked out another way. Recomputing the sphere after the matrices change makes the chain carbon pick up. `BondsPick2D` has the same shape. Drawing ran into the same stale sphere before and was worked around with `frustumCulled={false}`; picking was not. | High | Fixed (#23) |
| H3 | **A wavy bond is notched at every joint.** `Bonds2D` draws a wavy bond as a run of separate straight quads, and nothing fills the wedge-shaped gap between neighbours on the outside of each bend. Anti-aliased, each gap is a pale nick in the line: visible at fit-to-content size, plain once zoomed (`open-and-look`, `03-fitted` and `04-zoomed`). | Medium | Fixed (#31) |
